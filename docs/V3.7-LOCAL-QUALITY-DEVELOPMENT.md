# V3.7 Phase 3A — Local ROS quality

This is an owner-only development/research feature, **not a production FantasyPros integration**. It adds an informational **Best ROS Assets** section to Waivers. Current recommendations, lineup projections, trade verdicts, optimizer, protection/depth calculations and Markdown/JSON exports do not use it. Snapshot compatibility stays `3.2`.

## Import a private capture

Use Node 22.6+ and the existing project dependencies. Start in the repository directory:

```sh
npm run quality:import -- "path/to/private-capture.json"
```

The helper makes no provider calls. It validates and whitelists contract fields, reports mapped/unresolved records against any supplied player catalogue, and atomically writes `local-data/fantasypros-quality.json`. Invalid input leaves the previous cache intact. The entire `local-data/` directory is gitignored; never force-add it or copy captures into `public/`, source files or tracked test fixtures. Keep the original input outside tracked paths too. No credentials or API keys are needed.

Use [local-quality.example.json](local-quality.example.json) as the **synthetic format template**, not actual rankings. Replace its invented identities/ranks and timestamps with your manually supplied research evidence. This command does not interpret arbitrary CSV or raw API/MCP response formats.

Contract: `{version: 1, records: [{evidence, team, externalIds?, qualityStatus?}], mappings: {}, players: []}`. `evidence` uses the Phase 1 Player Quality fields: provider, season, ROS ranking type, scoring, redraft format, pool identity, provider/Sleeper IDs, name, position, overall/positional ranks, source-update or source-as-of metadata, and retrieval time. `team` is nullable. Optional `qualityStatus` can withhold stale/missing/unsupported/unresolved evidence; supplying `current` cannot override validation. Unknown fields are stripped, not forwarded to the browser.

`mappings` contains explicitly reviewed FantasyPros-ID → Sleeper-ID pairs. An optional `players` catalogue contains only `{sleeperId, name, position, team, externalIds?: {yahoo?, espn?}}`; never include team owners or league rosters. IDs are strings. Player names are displayed from the current Sleeper snapshot.

## Enable locally

Windows PowerShell:

```powershell
$env:LOCAL_QUALITY_ENABLED="1"
npm run dev
```

macOS/Linux shell:

```sh
LOCAL_QUALITY_ENABLED=1 npm run dev
```

Open the development app on your own computer at `http://localhost:8080`, load the league normally, and open **Waivers**. This feature intentionally rejects remote/proxied hosting, including a hosted Grok preview. A public URL is not a supported local workflow.

Use **Reload local capture** after an import; the section also checks the file every minute. Missing/disabled file: section hidden. Malformed file: a small local error, existing Waivers still works. Deleting the file is detected on reload or the next check. Refresh failure clears the local section rather than keeping unknown evidence visible.

## What it shows

- Current overall PPR ROS ranks, ascending; equal ranks use stable player IDs. No quality curve is selected.
- Optional positional annotation belongs to that same overall pool. Independently supplied positional pools remain separate and never fill an overall-rank gap.
- Current status and freshness basis per row. Source-update time, source-as-of date, or retrieval-only evidence is labeled explicitly. Retrieval-only evidence is not proof of an expert update.
- Coverage counts show ranked candidates versus the current offensive free-agent pool. “Available” means unrostered, including injured/on-bye players; it does not mean immediate help. The view does not select a drop or recommend a transaction.
- Evidence details show unresolved, stale, missing, unsupported/conflicting and positional-record counts. Record counts can exceed unique-player counts.

Evidence older than 72 hours by retrieval or supplied source metadata is withheld. Future/inconsistent dates and incompatible formats are withheld. Missing overall ECR stays unknown. Imported statuses cannot promote a stale record. The supported scope is PPR redraft with one QB; incompatible league settings do not yield ranked rows.

## Identity rules

1. Reviewed provider→Sleeper mapping, or an explicitly resolved stored Sleeper ID.
2. Unique shared Yahoo/ESPN ID from the supplied minimal catalogue.
3. Exact normalized name + position + nonempty matching team.
4. Otherwise unresolved; no automatic fuzzy matching.

Conflicting stored IDs, ambiguous matches, duplicate pool records and one-to-many/many-to-one resolved provider mappings are withheld. Normalization handles case, accents, spacing and punctuation; aliases and name changes require an explicit reviewed mapping. A supplied unverified Sleeper ID alone is insufficient. Current roster membership is checked again before display; rostered players never appear as free agents. Import counts without a catalogue are not verified mapping counts; the live snapshot provides the final eligible identities.

## Disable and production behavior

Stop the dev server, remove `LOCAL_QUALITY_ENABLED` (PowerShell: `Remove-Item Env:LOCAL_QUALITY_ENABLED`) and restart. Delete `local-data/fantasypros-quality.json` to remove the cache.

All builds, including `build:dev`, compile the feature flag to false. The lazy local panel and quality reader are excluded from application bundles. The file is never imported as a build asset. The file loader exists only in Vite development middleware; preview/deployed servers cannot read it. Local data is blocked from Vite static access and source imports as well as ignored by Git. No deployment, scheduled provider retrieval, MCP runtime dependency or secret was added.

Validation uses invented fixtures and a synthetic marker when checking built files. No actual research capture belongs in the tests, reports or Git. Production decisions and exports remain the established baseline regardless of local file contents.

Focused checks: `node --experimental-strip-types --test tests/quality/phase3a/*.test.*`. Build exclusion: `node tests/quality/phase3a/build-exclusion.mjs` (runs both builds with a temporary synthetic cache and restores any existing cache).
