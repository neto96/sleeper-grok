# V3.7.2 — Bundled ROS production release

Waivers now uses the shared V3.7 ROS view in production without a local flag or local files. The approved reference artifact contains 223 offensive records from the 2026 Week 11 ALL/PPR ROS top-250 capture, source date November 17. K/DST were excluded in the supplied capture. This is informational evidence; all existing recommendation, projection, trade, optimizer and export paths remain unchanged. Snapshot version stays 3.2.

## Refresh and freshness

Normal Refresh still fetches Sleeper data through the existing server function. The new snapshot recomputes available-player identity matches, availability labels, ROS coverage and decision context against the fixed capture. It never refreshes the ROS source date. The view says “ROS data · Nov 17, 2026 · Fixed Week 11 capture. Refresh updates Sleeper only.”

The existing 72-hour freshness policy remains unchanged. Because only a source day is known, age starts at November 17 00:00 UTC. After November 20 00:00 UTC (November 19, 6 PM Central), this capture is stale and ranks are withheld. The panel explicitly explains this; missing/stale/unmatched ranks remain unknown. A newer reference release is needed to restore current evidence. No build or Refresh resets the evidence clock.

## Artifact provenance and boundaries

`src/lib/ros-quality/week11-2026.json` was converted with the existing `convertEcr` importer and validated with `normalizeCapture`. Its source is the exact supplied `fantasypros-2026-week11-ppr-ros-all-offense.json`. No expert-update timestamp was supplied. The retrieval field uses the preserved capture-file creation timestamp (2026-11-17T14:39:38.046Z), explicitly documented in the source note; it is not an invented expert update.

Only normalized identity, team, rank, pool and provenance fields are included. Mappings and catalogue are empty; the existing exact resolver matches against the refreshed Sleeper state. ALL positional annotations remain annotations of ALL; they are never substituted for missing overall ranks. Raw file links, raw cache directories, credentials, tokens and provider network code are absent.

## Local workflow

`LOCAL_QUALITY_ENABLED=1` in development continues to select the private local source, including its existing missing/invalid-file behavior, single polling source, reload button and import commands. Without that flag the bundled source is used. Production/build:dev excludes `/__local-quality` and private local files even if the environment flag is set. Local and bundled sources render the same shared component and use the same quality/decision-context functions.
